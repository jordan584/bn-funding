# 极致紧凑 Funding 图片布局设计

## 目标

在不改变数据、排序、推送频率、图片数量和 GitHub 托管方式的前提下，缩短两张 Top10 Funding 图片的纵向高度，减少卡片内部与卡片之间的空白，使手机端快速扫榜更紧凑、精致。

## 已确认方向

采用视觉对比稿 B「极致紧凑」。相较最初版本，典型图片高度目标减少约 35%。图片继续以两张 Top10 输出；逻辑画布宽度缩至 800 SVG 单位，并以 2× 像素密度输出 1600 像素宽 PNG，用户点开原图后仍能清晰阅读小字。

## 布局规则

- 画布宽度从 1440 缩短至 800 SVG 单位，PNG 输出宽度从 2880 缩短至 1600 像素。
- 页面左右边距从 40 缩短至 24 SVG 单位，内容区宽度为 752 SVG 单位。
- 顶部标题区从 174 缩短至 110 SVG 单位，只保留标题以及单行“更新时间 + 排序说明”；不再单独占用两行。
- 资产标题行从 50 缩短至 36 SVG 单位。
- 表头从 34 缩短至 22 SVG 单位。
- 交易所数据行从 34 缩短至 22 SVG 单位。
- 资产卡片间距从 16 缩短至 6 SVG 单位，卡片圆角从 14 缩短至 10。
- 页脚从 72 缩短至 42 SVG 单位。
- 六列固定为 Venue、Funding、Int.、APR、7D / Day、7D APR；Venue 左对齐，其余五列使用各自列尾坐标右对齐，避免缩窄后数字互相挤占。
- 继续仅渲染存在数据的交易所；不存在的交易所不产生空白行。
- 保留 Rank、币种、Composite APR、Coverage、Funding、Interval、Next APR、7D Avg/Day、7D APR 全部信息。
- 表头使用更短文案，例如 `Funding`、`Int.`、`APR`、`7D / Day`，减少横向视觉噪音。
- 页脚压缩为单行，并保留正 Funding 含义及短历史 `*` 说明。

## 视觉层级

- 币种和 Composite APR 仍为卡片中的第一视觉焦点。
- Rank 使用蓝色强调；正 Funding 使用红色，负 Funding 使用绿色，语义不变。
- 卡片标题、表头、数据行字号按比例缩小，但 PNG 的 2× 输出不变；不得依靠浏览器缩放压缩 2880 像素旧图。
- 降低边框和分割线存在感，让高密度数据仍显得整洁。

## 数据与错误处理

本次不修改行情采集、跨交易所聚合、Top20 排序、历史 Funding 计算、图片上传、Google Chat 消息或状态文件逻辑。渲染输入不满 10 行时仍按现有规则失败，不生成残缺图片。

## 验证

- 测试固定全覆盖与两交易所覆盖场景的 SVG 高度，确保布局确实缩短。
- 验证 PNG 仍为两张、宽度为 1600 像素，并且内容非空。
- 验证所有数值列均在 800 SVG 单位画布内，最长测试数值不会与相邻列重叠。
- 验证所有字段、颜色语义、XML 转义和动态交易所过滤保持不变。
- 使用实时数据生成两张图片并人工检查手机阅读感。
- 完整运行类型检查、构建和测试后，再强制发送一轮 Google Chat 实图。

## 不在本次范围

- 不调整 Top20 排序逻辑或交易所权重。
- 不改为单张 Top20、网页、PDF 或其他托管方式。
- 不新增环境变量或部署依赖。
